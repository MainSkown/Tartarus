# GUI

- **Stack:** Vue 3 and Quasar (TypeScript, Vite) in **PWA mode**, served by the backend at
  `http://127.0.0.1:8080`, and installable as a standalone window.
- **Theme:** dark only, see the [design system](../design/design-system.md).
- **API access:** only through the client generated by `@hey-api/openapi-ts`
  (`src/api/generated`), wrapped by Pinia stores.

## App shell

```
┌──────────────────────────────────────────────────────────────────────────────────────────┐
│ ▼ TARTARUS            ● CAPE  ● GUEST  ● STORE      QUEUE 1      DISK 312/500 GB  [+ SUBMIT]│  header 48px
├────┬─────────────────────────────────────────────────────────────────────────────────────┤
│ ▤  │                                                                                     │
│ ⚑  │                               page content                                          │
│ ⛁  │                                                                                     │
│ ⚙  │                                                                                     │
└────┴─────────────────────────────────────────────────────────────────────────────────────┘
 mini drawer 56px: Dashboard · Rules · Guest VM · Settings  (labels in tooltips, expands on hover)
```

**Header**
- Wordmark `TARTARUS` in mono, `--blue-primary`, letter-spacing 4px.
- Three health dots: CAPE, Guest, Store (OpenSearch + Postgres). Each is green, amber or red
  with a tooltip giving the detail, and clicking one opens the health popover.
- Queue count and disk usage. The disk usage turns amber or red at the warn and block
  thresholds.
- The `+ SUBMIT` button is outlined in `--blue-primary`.
- While an analysis is running, a `● LIVE #42 01:12` chip appears and links to it.

**Global**
- `/` focuses the query bar on pages that have one. `Esc` closes drawers and dialogs.
- Toasts appear bottom-right (Quasar Notify `tt-*` types).
- Losing the WebSocket connection shows a slim amber top bar: "Reconnecting…".

## Routes

| Route | Page |
|---|---|
| `/` | Dashboard |
| `/analyses/:id` | Analysis workspace (defaults to the `live` tab while running, otherwise `overview`) |
| `/analyses/:id/:tab` | Tabs: `live`, `overview`, `processes`, `timeline`, `events`, `network`, `artifacts`, `detections`, `notes` |
| `/rules` | Sigma rules |
| `/guest` | Guest VM status and build wizard |
| `/settings` | Defaults and system info |

The query-bar state (query plus chips) and the selected process are kept in the URL query
(`?q=…&f=…&pid=…`), so reload and back/forward work and views can be bookmarked.

- **Table** (QTable, virtual scroll):
  - Clicking a row opens the analysis.
  - The row menu has Open, Re-ingest, Export and Delete.

- **Empty state:** when there are no analyses, the page shows a centred terminal-style block:
  `> no analyses yet` with a `[+ SUBMIT SAMPLE]` button. If the guest isn't ready, it shows
  `> guest VM not built` with a `[BUILD GUEST]` button instead.
- **Delete:** a confirm dialog with a red outlined button, showing the size that will be freed.

## Submit dialog

```
┌ SUBMIT SAMPLE ────────────────────────────────────────────┐
│ ┌───────────────────────────────────────────────────────┐ │
│ │        drop file here  ·  or  [BROWSE]                │ │
│ │        invoice.exe · 412 KB · PE32 executable          │ │
│ └───────────────────────────────────────────────────────┘ │
│ NETWORK  [ INETSIM ][ NONE ][ DROP ][ INTERNET ][ VPN ]   │
│ TIMEOUT  [ 180 ] s          PACKAGE [ auto        ▾]      │
│ [x] Interactive desktop   [ ] Full memory dump + Volatility│
│ TAGS     [ phishing × ] [+]                               │
│                                  [CANCEL]  [▶ DETONATE]   │
└───────────────────────────────────────────────────────────┘
```

- One file only.
- Shows SHA256 and type after upload, and warns if the hash was analysed before, with a link.
- The network route is a segmented radio. The default comes from Settings (INetSim).
  - `INTERNET` shows an inline amber warning: "Sample will reach the real internet from this
    host's public IP."
  - `VPN`, `WIREGUARD` and `SOCKS5` appear only if configured.
- Timeout: 60–1200 s.
- Package: `auto` by default; a select lists CAPE packages (exe, dll, doc, xls, ps1, js, …).
- The memory dump option warns: "Adds about 4 GB of disk and several minutes of processing."
- `DETONATE` is disabled when the guest isn't ready or disk is below the block threshold. The
  reason is shown inline.
- After submitting, the app navigates to `/analyses/:id`. If another analysis is running, it
  shows "Queued, position N".

## Analysis workspace (`/analyses/:id`)

**Header (all tabs)**

```
#42  invoice.exe   sha256 9f2c…a1 ⧉   ● LIVE 01:12 / 03:00   SCORE –   ⚠ HIGH   [phishing ×][+]
                                                       [⏹ STOP] [+60s] [⇩ EXPORT ▾] [🗑]
[ LIVE ][ OVERVIEW ][ PROCESSES ][ TIMELINE ][ EVENTS ][ NETWORK ][ ARTIFACTS ][ DETECTIONS ][ NOTES ]
> process.name:cmd.exe AND lane:network                                              [?] [✕]
[proc: cmd.exe ×] [NOT api: NtDelayExecution ×]
```

- **Phase indicator:**
  - `● LIVE` while running.
  - `PROCESSING…` with an indeterminate progress bar while CAPE processes the task.
  - `FINAL` when done.
  - Whenever partial data is shown, a small note says "live data, final report pending".
- **Query bar** (`.terminal-input-group`):
  - Shared by the Timeline, Events, Processes and Network tabs.
  - Field-name autocomplete comes from `/query/fields` (including aliases); value autocomplete
    comes after `field:`.
  - Errors are underlined in red with the message in a tooltip, and the query isn't run.
  - The `?` button opens the syntax cheat sheet.
  - Chips below the bar are quick filters. Clicking a chip toggles is/is-not, and `×` removes
    it.
- **Selected process:** selecting a process anywhere sets a `pid` chip that filters every tab.
- **Event detail drawer** (right side, 480px, overlay), opened from any event row or mark:
  - Header: summary, time, lane icon, process.
  - A fields table. Each row has `filter on` (+) and `filter out` (−) buttons and a copy button.
  - Raw JSON (code block).
  - Related events (links).
  - Tags and a note for this event.
  - `↑`/`↓` move to the previous or next event in the current list.

**Desktop panel**
- Keyboard input goes to the guest only while the panel has focus, shown by a blue glow
  border. `Esc` twice releases the focus.
- The panel has buttons for fullscreen, Ctrl+Alt+Del and the keyboard layout.
- No clipboard sync.

**Process tree**
- Shows live deltas.
- Severity icons with counts, and `⇢inject` markers.
- Clicking a process selects it, which filters the stream.

**Detections feed**
- Newest on top. Each new detection appears with a 1 s glow, plus a toast for high or critical.

**Event stream**
- Virtual list with auto-follow; `pause` freezes it.
- When paused, a counter shows the backlog: "+1 204 new".
- The query bar filters it server-side through the `subscribe` message.
- The API lane is hidden by default in the stream (it's very loud). A `[ ] show API calls`
  toggle brings it back.

### OVERVIEW tab

- **Stat tiles:**
  - Score.
  - Max severity.
  - Process count.
  - Event count by lane, as a horizontal bar per lane with direct labels.
  - Detections by severity.
  - Duration.
- **Detected families and extracted configs**, as key/value in code blocks.
- **Top detections**: the top 10, each linking to its detail.
- **Mini ATT&CK**: the tactics row with counts.
- **Screenshots strip**: a thumbnail carousel, click for a lightbox.
- **Sample static info**: type, size, hashes, imphash, signer, sections (for PEs) and strings
  (collapsible).

### PROCESSES tab
- The graph sits on the left, two-thirds wide (Cytoscape, dagre top-down layout, styles from the
  design system). The selected process's details sit on the right, one-third wide: command line,
  path, PID/PPID, integrity, start and end times, counts per lane, detections, network hosts,
  injected into or from, modules (collapsible), and tags and notes for the process.
- Toolbar:
  - Fit, zoom and layout reset.
  - Toggle network host nodes and toggle injection edges.
  - Export the graph as PNG.
- Switch between the graph and an indented tree (QTree) with the same data, for accessibility
  and large trees.

### TIMELINE tab
- Canvas timeline with six fixed lanes plus a detection track at the top (see the design
  system).
- A segmented radio sets the zoom: `fit`, `1m`, `10s`, `1s`. You can also zoom with the scroll
  wheel and pan by dragging.
- A brush selection adds a time-range chip.
- When a bucket holds more than 2 000 events (configurable), it's shown as an aggregated count
  bar. Zooming in loads the individual events (histogram endpoint, then search).
- Hover shows a tooltip, and clicking opens the event detail drawer.
- Below the canvas sits the Events table restricted to the visible time range, synced with the
  timeline.

### EVENTS tab
Full table (QTable virtual scroll, server-side `search_after` paging).

**Columns:** time, lane icon, process (pid), action, summary, and severity for detections.
Column chooser adds any catalog field.

**Left facet panel**, 240px and collapsible:
- Facets for `process.name`, lane, `event.action`, `api.name`, domain and rule, each with its
  top 10 and counts.
- Click a value to filter on it, alt-click to filter it out.

Sorting is by time, ascending or descending.

### NETWORK tab
Sub-tabs:
- **DNS:** query, type, answers, process.
- **HTTP:** method, URL, status, user agent, process.
- **TLS:** SNI, JA3/JA3S, process.
- **Flows:** 5-tuple, bytes, packets, process.
- **Alerts:** Suricata.

Every row has a process column and `filter on` actions. The `⇩ PCAP` button downloads the
PCAP. When INetSim answered, the row is marked `inetsim`.

### ARTIFACTS tab
Sub-tabs:
- **Dropped files:** name, path, size, type, SHA256, YARA hits, writer process, download.
- **Payloads & configs:** CAPE payloads with family, plus extracted config in a code block.
- **Process dumps.**
- **Memory:** dump size and download, and Volatility3 findings grouped by plugin.
- **Registry:** changes grouped by key, old and new value.
- **IOCs:** a deduplicated list with type, value, context and source, a copy button, and
  "filter events on this".

### DETECTIONS tab

**Left:** a list grouped by ruleset (Sigma, CAPE, YARA, Suricata). Each entry has a severity
badge, its name, a hit count and the technique ids.

**Right:** the selected detection.
- Description and references.
- The matched condition (code block).
- Triggering events (links).
- An `ATT&CK` view toggle that switches to the matrix (tactic columns × technique cells), with
  hit cells in severity colours and labelled with counts.

### NOTES tab
Every tag and note in this analysis, grouped by target (analysis, process, event), with links to
the targets.

Analysis-level notes are edited inline: a plain QInput textarea in autogrow mode with the
`.input-field` look, saved on blur with a "saved" toast.

### Export menu
- **IOCs:** STIX 2.1, MISP or CSV. These download immediately.
- **Report:** HTML or PDF. Choosing one opens a dialog with include options (notes,
  screenshots, raw IOCs) and runs as a job with progress; the file downloads when done.

## Rules (`/rules`)
- Table of Sigma rules:
  - Columns: enabled toggle, title, level badge, logsource category, status (valid, invalid or
    unsupported), path, hits (all analyses).
  - Filter by level, status and text.
- Clicking a row shows the rule YAML read-only in a code block, with the error if it's invalid.
- `[RELOAD]` button. The page also notes the rules directory path (`rules/sigma/custom/` for
  user rules).

## Guest VM (`/guest`)

- **Status card:**
  - OS label, resources and IP.
  - Snapshot name and date.
  - Health checks with icons and a `[RUN CHECKS]` button.
  - Last self-test result, including the pafish summary (info only).
- **Build wizard** (QStepper, vertical):
  1. Choose ISO: a list from `data/iso` showing the detected edition and version. If the list is
     empty, it explains where to put the ISO.
  2. Settings: edition, key (optional), locale, username, resources, decoys.
  3. Review: a summary plus a warning that rebuilding replaces the current guest after it
     passes its checks.
  4. Build: per-step progress (preflight → define → install → provision → snapshot → register →
     self-test) with a live log tail in a code block. The live desktop view is available
     during install and provision. Each step has Retry and the build has Resume.
- If the Defender Tamper Protection manual step is needed, the wizard pauses with instructions
  and shows the live desktop.

## Settings (`/settings`)
- **Defaults:** network route, timeout, interactive on/off, and the timeline aggregation
  threshold.
- **Disk thresholds:** warn and block.
- **Network routes:** read-only list of configured routes and how to add a VPN, WireGuard or
  SOCKS5 tunnel in `.env`.
- **About:**
  - Tartarus version, CAPE commit and the versions of each service.
  - Links to the docs.
  - A safety reminder.

## States and feedback (applies everywhere)

| State | Treatment |
|---|---|
| Loading | `.loader` centred in the panel. Tables show skeleton rows. |
| Empty | Terminal-style mono line `> no events match` plus a hint (`clear filters`) |
| Error (request) | `tt-error` toast with the message and code. The panel shows `> failed to load: <message>` with `[RETRY]` |
| Partial (live phase) | Info line "live data, final report pending" in `--text-gray` |
| Analysis failed | A red banner in the workspace header with the error, `[RE-INGEST]` if it was a report failure, and the live data still viewable |
| Disconnected | Amber top bar "Reconnecting…". Live views resume and backfill on reconnect |

## Frontend structure (`frontend/src/`)

| Path | Content |
|---|---|
| `api/` | `@hey-api/openapi-ts` output (do not edit; `npm run api:sync`) |
| `services/ws.ts` | Typed WebSocket client (reconnect with backoff, message types from the generated schema) |
| `stores/` | Pinia: `system`, `analyses`, `analysis` (current workspace: detail, query state, selection), `live`, `rules`, `guest` |
| `pages/` | One page component per route/tab |
| `components/` | `QueryBar`, `FilterChips`, `EventTable`, `EventDetailDrawer`, `ProcessGraph`, `ProcessTree`, `Timeline` (canvas), `DesktopViewer` (guacamole-common-js), `SeverityBadge`, `LaneIcon`, `StatTile`, `AttackMatrix`, `CodeBlock`, `TerminalEmpty` |
| `boot/` | `notify.ts` (toast types), `api.ts` (client base URL, error interceptor that raises toasts) |
| `css/` | `app.css` (the theme stylesheet, single source of the design tokens), `quasar.variables.scss` |

The PWA manifest:
- name "Tartarus", short name "Tartarus", `display: standalone`;
- `background_color` and `theme_color` `#000000`;
- icons in 192, 512 and maskable sizes.

The service worker caches only the app shell, never API responses.
